**JDG Księgowy 1.0.0** to pierwsza stabilna wersja darmowego, open-source'owego asystenta księgowego AI dla jednoosobowej działalności gospodarczej na ryczałcie. Wystawia faktury FA(3) i wysyła je do **KSeF 2.0**, buduje i składa **JPK_V7M** w bramce Ministerstwa Finansów, liczy **ryczałt, składki ZUS i PIT-28** — z czatu (OpenClaw), z **Claude Code**, z **Codex** albo z terminala.

### Najważniejsze w wersji 1.0

- **Jedno CLI `jdg` i serwer MCP z 34 narzędziami** — te same komendy dla człowieka, skryptu i agenta AI, z jednym kontraktem (`jdg schema`).
- **Wtyczka dla Claude Code i Codex** (skille + serwer MCP), instalowana z marketplace jednym poleceniem.
- **Bezpieczne wysyłki** — faktura do KSeF, JPK do urzędu i e-mail do klienta odchodzą dopiero po Twojej zgodzie na pokazane podsumowanie.
- **Pełny łańcuch numeru KSeF**: faktura → KSeF → numer i kod QR na fakturze → `NrKSeF` w JPK_V7M.
- **Reguły podatkowe 2026**: terminy w dni robocze, składka zdrowotna liczona narastająco, mikrorachunek podatkowy, PIT-28 z kwotą do dopłaty.

## Instalacja

Serwer z OpenClaw (Ollama lokalnie albo dowolny model):

```bash
git clone https://github.com/dithiothreitol/jdg-ksiegowy.git
cd jdg-ksiegowy
./setup.sh        # uv, `jdg` w PATH, .env, baza, OpenClaw i rejestracja narzędzi MCP
```

Claude Code i Codex — ta sama wtyczka:

```bash
uv tool install --editable .     # `jdg` w PATH: CLI i serwer MCP (dane w tym katalogu)
claude plugin marketplace add ./ && claude plugin install jdg-ksiegowy@jdg-ksiegowy
codex plugin marketplace add ./ && codex plugin add jdg-ksiegowy@jdg-ksiegowy
```

Bez klonowania repozytorium: `uv tool install git+https://github.com/dithiothreitol/jdg-ksiegowy@v1.0.0`, a potem w Claude Code `/plugin install jdg-ksiegowy --marketplace dithiothreitol/jdg-ksiegowy`. Plik `.env` i dane trafiają wtedy do `~/.jdg-ksiegowy` (albo do katalogu wskazanego w `JDG_HOME`).

Docker compose — sekrety i baza tylko w usłudze `jdg-mcp`:

```bash
echo "JDG_MCP_TOKEN=$(openssl rand -hex 32)" >> .env
docker compose up -d --build
docker compose exec openclaw sh -c 'openclaw mcp add jdg --url http://jdg-mcp:8765/mcp \
  --transport streamable-http --header "Authorization=Bearer $JDG_MCP_TOKEN"'
```

Szczegóły: [INSTALL.md](https://github.com/dithiothreitol/jdg-ksiegowy/blob/v1.0.0/INSTALL.md) i [DEPLOYMENT.md](https://github.com/dithiothreitol/jdg-ksiegowy/blob/v1.0.0/DEPLOYMENT.md).

## Co nowego

### Faktury i KSeF 2.0

- Faktury FA(3) z wieloma pozycjami: stawki 23/8/5/0 % oraz `zw`, `np`, `0_wdt`, `0_exp`, kody GTU. Usługa dla firmy z innego kraju UE trafia do FA(3) jako „np II” i do JPK jako K_11 + K_12 — spójnie w obu ewidencjach.
- Nabywcy z Unii Europejskiej (numer VAT-UE) i spoza UE.
- Faktury korygujące FA(3) KOR z odwołaniem do numeru KSeF faktury pierwotnej (`jdg invoice correct`).
- Po wysyłce do KSeF rejestr przechowuje numer KSeF, datę przyjęcia i UPO, a faktura DOCX/PDF dostaje numer KSeF i kod QR weryfikacji (KOD I).
- Wysyłka odporna na przeciążenie KSeF: faktura przyjęta, ale jeszcze bez numeru, dostaje status `pending` i jest zablokowana przed ponowną wysyłką (bez ryzyka duplikatu w KSeF); faktura odrzucona może zostać poprawiona i wysłana ponownie.
- Biała lista podatników VAT: `jdg buyer lookup`, automatyczne dane nowego kontrahenta i ostrzeżenie, gdy nie jest czynnym podatnikiem VAT.
- Faktury zakupowe pobierane z KSeF (`jdg ksef inbox`) z opisem z pozycji FA(3); uzupełnianie numerów KSeF dla faktur wysłanych przed 1.0 (`jdg ksef backfill`).

### JPK_V7M, JPK_EWP i bramka MF

- Numer KSeF (`NrKSeF`) zamiast `BFK` w ewidencji sprzedaży i zakupów.
- Automatyczne przeniesienie nadwyżki VAT z poprzedniej deklaracji (P_39), pola K_10–K_22 i oznaczenia GTU.
- Kwoty deklaracji w pełnych złotych liczone z już zaokrąglonych pól (P_38 = P_16 + P_18 + P_20 + …, P_51 = P_38 − P_48) — zgodnie z kontrolami logicznymi MF.
- Walidacja XSD offline, rejestr złożonych deklaracji, wznawianie sprawdzania statusu i pobieranie UPO (`jdg jpk status`).
- Korekty JPK numerowane `_K1`, `_K2`…; narzędzie odmawia ponownego złożenia deklaracji pierwotnej, gdy zna już przyjętą.

### Ryczałt, ZUS i PIT-28

- Terminy przesuwane na najbliższy dzień roboczy (z Wigilią wolną od 2025 r.); ryczałt za grudzień do 20 stycznia, PIT-28 i JPK_EWP do 30 kwietnia.
- Składka zdrowotna według przychodu narastająco od początku roku, pomniejszonego o zapłacone składki społeczne (`jdg tax zus`).
- Rejestr wpłat (`jdg tax pay`) zamyka przypomnienia i zasila odliczenia; mikrorachunek podatkowy w `jdg status`.
- PIT-28: odliczenia, podstawa roczna, wpłacone zaliczki i kwota do dopłaty. Ryczałt zaokrąglany do pełnych złotych zgodnie z art. 63 Ordynacji podatkowej.

### Koszty i OCR faktur

- Odczyt faktur zakupu (PDF, zdjęcia) przez lokalny model wizyjny w Ollama z wymuszonym schematem JSON, z fallbackiem na Claude (structured outputs).
- Kontrole odczytu — suma kontrolna NIP, netto + VAT = brutto, zgodność stawki, data, duplikat w rejestrze — blokują zapis błędnych danych.

### CLI, serwer MCP i wtyczka

- `jdg` (Typer + Rich): tabele w terminalu, koperta JSON dla agentów i skryptów, stałe kody wyjścia, kontrakt wszystkich komend w `jdg schema`.
- `jdg mcp serve`: 34 narzędzia MCP generowane z tych samych komend — stdio dla Claude Code i Codex, streamable HTTP z tokenem Bearer dla Dockera.
- Wtyczka `jdg-ksiegowy` w formatach Claude Code i Agent Plugins 1.0 (Codex) oraz marketplace'y w repozytorium.
- Docker compose z osobną usługą `jdg-mcp` (healthcheck, bez portu na hoście); kontener OpenClaw nie ma dostępu do tokenu KSeF, danych MF ani SMTP.
- Szyfrowany backup (`jdg backup`): spójna kopia SQLite, szyfrowanie Fernet, weryfikacja po zapisie i retencja.
- Kontrakty cykliczne (`jdg contract run`) nadrabiają fakturę za bieżący miesiąc po przerwie w pracy serwera, a błąd jednego kontraktu nie wstrzymuje pozostałych.

## Bezpieczeństwo

- Czynności nieodwracalne (`ksef_send`, `invoice_mail`, `jpk_submit`) są dwufazowe: najpierw podsumowanie i token powiązany z treścią, środowiskiem i datą; wykonanie wyłącznie z tym tokenem.
- W Claude Code hook `PreToolUse` wymusza okno zgody na wywołanie z tokenem — model nie zatwierdzi wysyłki za Ciebie, także w trybie auto.
- Treść faktur, danych z KSeF i OCR jest traktowana jako dane, a nie polecenia; dziennik audytu (`jdg audit`) zapisuje każdą wysyłkę i każdą odmowę.

## Aktualizacja z wersji 0.x

1. Zrób kopię katalogu `data/` (co najmniej pliku `data/jdg_ksiegowy.db`).
2. `git pull && uv sync --frozen && uv tool install --editable . --force`
3. Pierwsze uruchomienie `jdg` automatycznie migruje bazę (Alembic): kwoty przechodzą na grosze, pozycje faktur są odtwarzane z plików FA(3).
4. Skrypty skilli z 0.x zastąpiło CLI `jdg` — sprawdź własne zadania cron (wzory w [CRON.md](https://github.com/dithiothreitol/jdg-ksiegowy/blob/v1.0.0/CRON.md)).
5. Generator pliku KEDU (DRA) został usunięty: kwoty składek podaje `jdg tax zus`, a deklarację DRA składasz w PUE/eZUS.
6. Nowe zmienne w `.env`: `BACKUP_KEY` (backup), `JDG_MCP_TOKEN` (Docker), opcjonalnie `JDG_HOME` i `BACKUP_DIR`.
7. Docker: compose ma teraz dwie usługi — po `docker compose up -d` jednorazowo zarejestruj serwer MCP w OpenClaw (polecenie w sekcji Instalacja).
8. `jdg ksef backfill`, a po sprawdzeniu `jdg ksef backfill --apply`, aby faktury wysłane przed 1.0 miały numer KSeF w JPK_V7M.

## Znane ograniczenia

- Obsługiwany jest wyłącznie ryczałt od przychodów ewidencjonowanych (bez zasad ogólnych i podatku liniowego).
- Parametry ZUS są wbudowane dla 2026 r.; wartości na 2027 r. trzeba dopisać po ich publikacji — `jdg doctor` ostrzega o braku.
- Wtyczka wymaga `jdg` w PATH (`uv tool install`).
- W Codex wtyczka nie instaluje hooka zgody: ochronę zapewnia dwufazowy token i zatwierdzanie wywołań narzędzi przez Codex.
- Przypomnienia cykliczne trzeba zarejestrować w OpenClaw ([CRON.md](https://github.com/dithiothreitol/jdg-ksiegowy/blob/v1.0.0/CRON.md)); brak powiadomień push o zaległych płatnościach.
- Narzędzie wspiera prowadzenie rozliczeń, ale nie zastępuje doradcy podatkowego.

## In English

**JDG Księgowy 1.0.0** is the first stable release of an open-source AI accounting assistant for Polish sole proprietorships (JDG) on the lump-sum tax (ryczałt). It issues FA(3) e-invoices and submits them to **KSeF 2.0**, Poland's National e-Invoicing System, builds and files **JPK_V7M** VAT returns through the Ministry of Finance gateway, and calculates **ZUS** social security contributions and the annual **PIT-28** return. All features are available as one CLI (`jdg`), as an **MCP server** with 34 tools and as a **Claude Code and Codex plugin**; every irreversible action requires explicit human approval of a summary. Python 3.12+, MIT license, self-hosted with Ollama or any LLM.
