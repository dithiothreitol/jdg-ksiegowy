**JDG Księgowy 1.0.1** jest wydaniem poprawkowym otwartego asystenta księgowego AI dla jednoosobowej działalności gospodarczej na ryczałcie. Wydanie poprawia fakturę PDF wysyłaną klientom, która otrzymała format A4 i czytelny zapis kwot, a komunikaty CLI `jdg`, serwera MCP i wtyczki dla Claude Code oraz Codex zostały zapisane z polskimi znakami.

### Najważniejsze w wersji 1.0.1

- **Faktura PDF w formacie A4**, w której kolumny tabeli zachowują szerokość, a kwoty nie są dzielone między wiersze.
- **Polski zapis kwot** na fakturze (`12 000,00 PLN`) oraz etykiety z polskimi znakami, takie jak „Do zapłaty” i „Termin płatności”.
- **Komunikaty z polskimi znakami** w pomocy, błędach, podsumowaniach przed zgodą, przypomnieniach i wiadomości e-mail z fakturą.
- **Poprawne polskie znaki w odpowiedziach dla agenta AI na Windows**, ponieważ `jdg` zapisuje wynik w UTF-8 także wtedy, gdy wyjście jest przekazywane potokiem.

## Co zostało poprawione

### Faktura PDF dla klienta

W wizualizacji faktury (DOCX oraz PDF tworzony przez LibreOffice i wysyłany poleceniem `jdg invoice mail`) szerokości kolumn zostały zapisane zarówno w komórkach, jak i w siatce tabeli, dzięki czemu LibreOffice nie zawęża kolumn, a kwoty pozostają w jednym wierszu. Strona ma format A4 z marginesami 1,5 cm, kwoty są zapisywane z twardą spacją jako separatorem tysięcy i z przecinkiem dziesiętnym, a etykiety zawierają polskie znaki.

### Komunikaty CLI, serwera MCP i wtyczki

Pomoc poleceń i opcji, komunikaty błędów z podpowiedziami, podsumowania wyświetlane przed zgodą, ostrzeżenia, etykiety przypomnień (np. „Ryczałt za 10/2026”) oraz treść wiadomości e-mail z fakturą dla klienta zostały zapisane z polskimi znakami. Ta sama zmiana obejmuje opisy narzędzi serwera MCP, wynik `jdg schema` oraz okno zgody, które hook wtyczki wyświetla w Claude Code przed wysyłką.

### Kodowanie wyjścia na Windows

Na Windows Python w wersjach 3.12–3.14 koduje wyjście przekazywane potokiem w stronie kodowej systemu (cp1250 lub cp1252), w związku z czym agent otrzymywał polskie znaki jako błędne bajty, a przy stronie cp1252 polecenie wypisujące polskie znaki kończyło się błędem `UnicodeEncodeError`. Od wersji 1.0.1 `jdg` przełącza standardowe wyjście i wyjście błędów na UTF-8, dzięki czemu Claude Code, Codex i skrypty otrzymują poprawny tekst niezależnie od ustawień regionalnych systemu.

## Aktualizacja

Z klonu repozytorium:

```bash
git pull && uv sync --frozen && uv tool install --editable . --force
```

Bez klonowania repozytorium: `uv tool install --force git+https://github.com/dithiothreitol/jdg-ksiegowy@v1.0.1`. W Dockerze obraz zostanie zaktualizowany poleceniem `docker compose up -d --build`.

- Aktualizacja nie zmienia schematu bazy, w związku z czym migracja nie jest wymagana.
- Klucze JSON, kody wyjścia i parametry poleceń nie zostały zmienione, natomiast skrypty porównujące treść komunikatów (np. fragment „juz wyslany”) powinny zostać dostosowane do zapisu z polskimi znakami.
- Wydarzenia w Kalendarzu Google otrzymają nowe tytuły przy najbliższej synchronizacji (`jdg calendar sync`).
- Pliki DOCX i PDF faktur wystawionych przed aktualizacją nie są generowane ponownie, natomiast nowy szablon obejmuje faktury wystawione po aktualizacji oraz wizualizacje tworzone po wysyłce do KSeF.

## Weryfikacja

385 testów offline zostało zaliczonych na Pythonie 3.12–3.15, a ruff i mypy nie zgłaszają błędów. Szablon faktury został sprawdzony na pliku PDF wygenerowanym przez LibreOffice dla faktury przyjętej w środowisku testowym KSeF, a kodowanie wyjścia zostało objęte testem regresji, który uruchamia `jdg` w potoku z kodowaniem cp1252.

## In English

**JDG Księgowy 1.0.1** is a patch release of the open-source AI accounting assistant for Polish sole proprietorships (JDG). The invoice PDF sent to clients now uses A4 pages with stable column widths and Polish number formatting, all CLI, MCP and plugin messages use proper Polish characters, and `jdg` writes UTF-8 to pipes on Windows, so AI agents such as Claude Code and Codex receive correct text. The JSON contract (keys, exit codes and parameters) is unchanged and no database migration is required.
